# 拾光 · 校园失物招领系统

拾光是一个面向校园场景的失物招领前端原型，覆盖物品发现、信息发布、认领申请、审核管理、公告管理和数据总览等核心流程。项目使用 **Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus** 构建，当前通过 Pinia 内存 Mock 数据演示完整业务闭环，并实现了基于路由守卫的前端 RBAC 权限控制。

## 技术栈

- **Vue 3**：`<script setup>` + Composition API
- **Vite**：开发服务器与生产构建
- **TypeScript**：领域类型与类型安全，`vue-tsc --noEmit` 类型检查
- **Pinia**：集中式状态管理（角色、认证、物品、认领、公告、评论）
- **Vue Router**：路由元信息、登录守卫与角色访问控制（RBAC）
- **Element Plus**：表单、表格、弹窗、上传、分页等 UI 组件
- **ECharts**：已加入依赖，用于后续数据大屏可视化

## 功能清单

### 学生端

- **用户注册**：注册页开放普通学生注册，默认角色为普通学生（`role = student`）。
- **登录鉴权**：登录页去除身份选择，仅需账号 + 密码，通过真实账号密码匹配后按角色进入对应工作台。
- **物品发现（首页）**：物品卡片列表，支持关键词模糊搜索（名称/地点/标签）、类型（全部/寻物/招领）、分类、地点、时间（近 3/7/30 天）多维筛选，支持分页。
- **详情弹窗**：图片轮播、物品标签、描述、统计信息（浏览/点赞/收藏），评论区支持发表评论、楼中楼回复、点赞，点赞收藏逻辑即时反馈。
- **认领 / 提供线索（双重业务分支）**：
  - **招领物品（`found`）**：非发布者可点击【申请认领】，填写认领说明 + 证明材料图片后提交；提交后弹窗不关闭，切换到“查看发布者联系方式”步骤，需**勾选隐私承诺**后方可查看发布者联系方式并一键复制。
  - **寻物物品（`lost`）**：详情页对非发布者显示【提供线索】按钮，填写线索描述 + 图片提交；**联系方式静默带入**（取当前登录用户注册时填写的 `contact`，前端不展示输入框），线索直接通知发布者。
- **我的认领**：展示自己提交的认领申请及状态；每一行有【查看联系方式】按钮，点击后弹出隐私承诺勾选框，勾选后才展示发布者联系方式（从对应物品 `contact` 字段取）+ 一键复制。
- **消息通知**：右上角铃铛按当前用户展示系统通知和未读数；新线索、新认领申请、认领结果等场景都会生成通知；支持**单条删除**（悬停出现删除按钮）与**一键清空**（带二次确认），通知与已读状态持久化到浏览器 localStorage。
- **信息发布**：
  - 物品类型（丢失/拾取）+ 物品名称 + 联系方式；
  - **多标签多选**（数码/证件/日用/服饰/书籍/其他）；
  - **动态地点联动选择器**：根据所选建筑类型（宿舍楼/教学楼/食堂/桥边操场）动态展示不同的输入项，并自动拼接完整地址；
  - **图片上传**：仅图片格式、最多 3 张、本地预览与删除。
- **我的发布 / 我的认领**：查看当前用户发布记录、认领和线索记录；失物发布者可从“查看线索(n)”查看线索人、说明和联系方式。待审核发布可删除或编辑，招领中/待认领发布可撤回，已撤回发布可编辑后重新提交审核。
- 表单校验：物品名称、标签、地点、联系方式、详细描述、图片数量均有前端校验与错误提示。

### 隐私保护机制

- 发布者联系方式（`item.contact`）**默认隐藏**，不直接展示在详情页或列表中。
- 申请认领时，申请者在提交认领说明后需**勾选隐私承诺**（“我承诺仅将该联系方式用于找回该物品，绝不恶意骚扰”）才能查看发布者联系方式；承诺框为强制必选，未勾选时联系方式不可见。
- “我的认领”列表提供【查看联系方式】常驻入口，同样需要勾选隐私承诺后方可查看，并支持一键复制。
- 发布者同意认领后发送给申请人的系统通知**不再包含具体联系方式**，引导申请人前往“我的认领”查看，避免联系方式冗余传播。

### 失物招领管理员端

- **审核中心**：管理员只审核待审核物品信息，可通过详情抽屉对照图集和发布内容后处理。
- **物品管理**：全部物品表格，支持搜索与状态筛选，可对物品「编辑」「下架/上架」「删除」（删除/下架带二次确认）；支持**表格勾选 + 批量删除**（最左侧 `selection` 列勾选多行，工具栏【批量删除】按钮带二次确认“确定要删除选中的 X 件物品吗？删除后无法恢复。”）。

### 系统管理员端

- **数据总览**：指标卡（累计发布/成功归还/待处理/归还率）、近 30 日趋势图、高频地点排名（当前为 CSS 占位图表）。
- **账号管理**：以表格展示所有注册用户（账号、昵称、角色、状态），支持**修改角色**（可将普通学生提升为失物招领管理员或系统管理员）与**禁用/启用**账号。
- **公告管理**：公告列表与编辑入口（占位）。

## 启动项目

环境要求：Node.js 18+，npm 9+。

```bash
# 进入项目目录
cd lost-and-found

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

浏览器打开终端输出的本地地址即可。其他常用命令：

```bash
# TypeScript 类型检查
npm run type-check

# 生产构建
npm run build

# 预览生产构建结果
npm run preview
```

## 演示账号

登录页已去除身份选择，改为**纯账号密码匹配**；登录成功后会根据账号对应的角色进入对应工作台。系统内置以下初始账号（本地 Mock 数据，持久化在 `localStorage`，不连接真实后端）：

| 角色 | 账号 | 密码 | 可见菜单 | 主要能力 |
| --- | --- | --- | --- | --- |
| 系统管理员 | `sysadmin` | `123456` | 数据总览、账号管理、公告管理 | 查看统计数据、**在【账号管理】中分配/修改角色、禁用/启用账号**、管理公告 |
| 普通学生 | `2023010218` | `123456` | 发现物品、发布信息、我的发布、我的认领 | 搜索、发布、详情查看、点赞收藏评论、申请认领 |
| 失物招领管理员 | `teacher01` | `123456` | 审核中心、物品管理 | 审核发布、维护物品状态（编辑/下架/删除） |

> 内置于 store 中的 **`sysadmin / 123456`** 是系统初始最高权限账号，不可被前端注册或修改；角色分配与提权由该账号在【账号管理】页面完成。新注册用户一律为普通学生，需由系统管理员提权后方可使用管理员工作台。

## 权限与路由

- 登录后才能访问 `/app` 下受保护的工作台；未登录访问时会跳转到 `/login?redirect=<原地址>`。
- 各路由通过 `meta.roles` 声明允许角色，菜单通过 `src/navigation.ts` 按角色过滤；即便直接输入地址，路由守卫也会拦截越权访问并返回当前角色首页。
- 只做前端 RBAC 仅用于体验，真实后端仍需二次校验（Token、身份、数据操作权限）。

## 当前边界

- 数据保存在 Pinia 内存中，用户数据持久化到 `localStorage`（`registered_users`），刷新后可恢复。
- 图片为本地 `URL.createObjectURL` 预览，尚未上传服务器。
- 账号登录基于本地 Mock 用户表 + Mock Token，未接入真实后端。
- 数据大屏目前使用 CSS 占位图表，ECharts 尚未接入。
- 真实版本需接入 Go 后端、数据库、Token/JWT、对象存储及后端权限校验。
